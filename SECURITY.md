# Security Policy

## Supported releases

Security fixes are prepared for the current stable release line. The current prerelease may receive the same fix as part of beta validation. Before reporting a problem, reproduce it with the newest applicable published release when that can be done safely.

## Reporting a vulnerability

Do not publish suspected vulnerabilities, exploit details, access tokens, diagnostics, or private entity data in a public issue.

Use GitHub's **Report a vulnerability** action on the repository's Security page when private vulnerability reporting is enabled. Include:

- the Smart Shading and Home Assistant versions;
- the affected component and realistic impact;
- minimal reproduction steps or a proof of concept;
- relevant sanitized logs or diagnostics;
- any known mitigation.

If the private reporting action is not available, open a minimal public issue stating only that you need a private security contact. Do not include vulnerability details there.

There is no guaranteed response-time SLA. Maintainers will acknowledge, validate, coordinate a fix and disclosure, and credit the reporter when appropriate and desired. Please allow a reasonable remediation period before public disclosure.

For ordinary setup questions and non-security defects, use [SUPPORT.md](SUPPORT.md) and the repository issue templates.
